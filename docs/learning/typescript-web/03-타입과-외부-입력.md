# 3. TypeScript: 타입으로 외부 입력 다루기

## 이번 문서에서 배울 내용

- 외부에서 들어온 값(서버 응답, 저장소, URL)을 왜 `unknown`으로 받는지
- `any`와 `as`를 남발하면 생기는 문제
- 상태를 판별 유니온으로 나누는 방법

## 1. 외부 값은 믿지 않고 좁힌다

서버 응답은 타입이 붙어 있지만, 실제 값은 TypeScript가 보장하지 않습니다. `as User`로 단정하면 컴파일러는 조용해지지만, 실제 데이터가 다르면 화면에서 터집니다.

나쁜 예:

```ts
const user = (await res.json()) as User;
```

좋은 예:

```ts
const raw: unknown = await res.json();
const user = parseUser(raw); // 형태를 확인하고 User로 좁힌다
```

`unknown`은 "아직 무엇인지 모른다"는 뜻입니다. 쓰기 전에 검사해야 하므로, 잘못된 값이 안쪽 코드로 흘러 들어가는 것을 막습니다.

## 2. `any`와 `as`는 최후의 수단

- `any`는 타입 검사를 통째로 끄는 것입니다.
- `as`는 "내가 맞다고 보장한다"는 선언입니다. 틀려도 컴파일러가 알려 주지 않습니다.
- `@ts-ignore`는 이유를 모른 채 오류를 숨깁니다. 정말 불가피하다면 `@ts-expect-error`와 이유를 함께 씁니다.

## 3. 상태는 판별 유니온으로

로딩, 성공, 실패를 `boolean` 여러 개로 표현하면 "로딩이면서 실패" 같은 불가능한 조합이 생깁니다.

```ts
type LoadState<T> =
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };
```

이렇게 나누면 `status`로 분기할 때 각 경우에 무엇이 있는지 타입이 알려 줍니다.

## 4. 형태 검사에는 `satisfies`

객체가 특정 타입을 만족하는지 확인하면서도, 값의 구체적인 타입은 그대로 남기고 싶을 때 `satisfies`를 씁니다.

```ts
const routes = {
  home: "/",
  book: "/books/:id",
} satisfies Record<string, string>;
```

## 핵심 정리

- 외부 입력은 `unknown`으로 받아 검사한 뒤 좁힙니다.
- `any`, `as`, `@ts-ignore`는 이유 없이 쓰지 않습니다.
- 상태는 판별 유니온으로 나눠 불가능한 조합을 막습니다.
- 객체 형태 검사는 `satisfies`를 활용합니다.
