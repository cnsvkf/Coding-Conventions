# 2. TypeScript·웹: 역할과 쓰임이 보이는 이름 짓기

## 이번 문서에서 배울 내용

이름을 읽었을 때 값이나 코드가 맡은 역할을 알 수 있도록 작성하고, 웹 코드의 종류에 따라 프로젝트에서 정한 이름 규칙을 적용합니다. 같은 기능을 찾거나 고칠 때 이름이 길잡이가 됩니다.

## 먼저 역할을 드러내기

`data`, `value`, `item`, `result`, `temp`, `obj`, `manager`처럼 뜻이 넓은 이름은 문맥만으로 대상을 구별하기 어려울 때 모호해집니다.

| 모호한 이름 | 역할이 드러나는 이름 |
|---|---|
| `result` | `loginResult` |
| `item` | `selectedBook` |
| `loading` | `isLoading` |
| `submit` | `handleSearchSubmit` |

다음 코드처럼 이름만으로 상태의 의미가 분명하지 않을 때는 역할을 드러내는 표현을 선택합니다.

```ts
const loading = true;
```

```ts
const isLoading = true;
```

`result`나 `item`이 항상 틀린 것은 아닙니다. 가까운 문맥에서 뜻이 명확하면 짧은 이름을 쓸 수 있습니다. 비슷한 값과 동작이 함께 있을 때 서로 헷갈리지 않는지를 기준으로 판단합니다.

## 코드 종류에 맞는 이름 규칙

전역 스킬은 웹 프론트엔드 코드에 아래와 같은 구분을 적용합니다.

| 코드 종류 | 이름 규칙 | 예시 |
|---|---|---|
| 컴포넌트 | `PascalCase` | `BookList` |
| 커스텀 훅 | `use`로 시작 | `useCurrentUser` |
| 이벤트 핸들러 | `handle`로 시작 | `handleSearchSubmit` |
| 이벤트 콜백 prop | `on`으로 시작 | `onSearchSubmit` |
| boolean 값 | `is`, `has`, `should` 중 하나로 시작 | `isLoading`, `hasAccess`, `shouldRefresh` |

이름은 코드의 역할뿐 아니라 사용되는 자리도 알려 줍니다. 예를 들어 `handleSearchSubmit`은 이벤트 처리 동작이고, `onSearchSubmit`은 컴포넌트에 전달되는 콜백이라는 점을 구분할 수 있습니다.

파일명은 저장소마다 관례가 다를 수 있으므로 기존 파일을 확인합니다. 어떤 프로젝트가 컴포넌트 파일에 `PascalCase`를 쓰고 다른 프로젝트가 `kebab-case`를 쓰더라도, 새 파일은 해당 저장소의 패턴을 이어갑니다.

## 이름을 정할 때 살펴볼 점

- 이름이 값이나 함수의 역할을 설명하는가?
- 컴포넌트·훅·핸들러·콜백·boolean의 종류가 이름에서 드러나는가?
- 같은 범위의 다른 이름과 겹치거나 헷갈리지 않는가?
- 파일명과 대소문자 규칙이 기존 프로젝트와 맞는가?

## 핵심 정리

- 모호한 이름은 역할이 드러나도록 구체화합니다.
- 컴포넌트·훅·이벤트 처리·콜백·boolean은 코드 종류에 맞는 접두사와 표기법을 적용합니다.
- 파일명과 세부 표기 규칙은 프로젝트 관례를 따릅니다.
- 짧음만을 기준으로 이름을 줄이지 말고, 문맥에서 충분히 구별되는지 확인합니다.
