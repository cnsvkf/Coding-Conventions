# 2. 작업 전에 코드부터 조사하기

## 이번 문서에서 배울 내용

낯선 코드 영역을 고치기 전에, 무엇을 읽고 어떤 질문에 답해야 하는지 익힙니다. 추측으로 구현하면 기존 구조와 어긋난 코드가 생기기 쉽습니다.

## 왜 조사부터 할까요?

코드는 보이는 것보다 많은 약속을 담고 있습니다. 어떤 이름을 쓰는지, 상태를 어디서 관리하는지, 화면 이동을 어떻게 하는지가 모두 그렇습니다. 이 약속을 모른 채 새 코드를 쓰면 같은 일을 두 가지 방식으로 하게 됩니다.

## 조사할 때 던질 질문

1. 저장소에 **안내 문서**가 있는가? (`AGENTS.md`, 프로젝트 스킬, README)
2. 새 기능과 **가장 가까운 기존 기능**은 어디에 있는가?
3. 그 기능은 **어떤 도구와 구조**를 쓰는가?
4. 여러 기능에서 **반복되는 패턴**(이름, 파일 위치, 상태 관리, 화면 이동)은 무엇인가?

## 예시: 설정 화면에 항목 추가하기

설정 화면에 "알림 끄기" 스위치를 추가한다고 해 봅시다.

- 먼저 기존 설정 화면이 **어떤 상태 객체**로 값을 들고 있는지 찾습니다.
- 값을 바꾸는 함수가 **어느 계층**에 있는지 따라갑니다.
- 저장소에 설정 값을 **어떤 저장 방식**으로 보관하는지 확인합니다.

이 세 가지를 확인하면, 새 스위치도 기존 설정 항목과 같은 방식으로 연결할 수 있습니다.

## 조사 범위는 작업에 맞게

전체 프로젝트를 다 읽을 필요는 없습니다. 작업과 직접 연결된 화면, 상태, 데이터 흐름까지만 봅니다. 범위를 정하기 어렵다면 "이 작업이 바뀌면 어디까지 영향이 갈까?"를 먼저 생각합니다.

## 조사 결과를 남기기

찾은 내용은 짧게 정리해 두면 리뷰와 나중의 작업에 도움이 됩니다.

- 참고한 기존 파일 경로
- 따르기로 한 이름 규칙과 구조
- 새로 도입하려는 도구가 있다면, 기존 방식으로 안 되는 이유

## 핵심 정리

- 구현 전에 안내 문서와 비슷한 기존 코드를 먼저 읽습니다.
- 이미 쓰는 구조와 도구를 우선 이어서 씁니다.
- 새 도구나 구조를 넣으려면 기존 방식으로 해결할 수 없는 이유를 설명할 수 있어야 합니다.

## 복습 질문

1. 구현 전에 조사해야 하는 대표적인 질문 세 가지는 무엇인가요?
2. 기존 설정 화면과 다른 방식으로 새 스위치를 만들면 어떤 문제가 생기나요?
3. 조사 범위를 정할 때 기준으로 삼을 질문은 무엇인가요?
